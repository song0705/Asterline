# Asterline v0.2.8

> 这一版的主线是让团队会话真正接上各自的原生 CLI：Codex 成员不再把每一轮
> 当成一次孤立的 `exec`，而是保有可恢复的 App Server thread；模型、审批和工具
> 事件都留在同一条原生线程里。Team 编辑器也不再拿静态猜测冒充 CLI 设置——启动时
> 读取本机可用模型与权限默认值，失败才允许对选中成员手动刷新。日常交互则收紧为
> Asterline 自己能诚实完成的动作：原生命令进入原生会话，技能只经对应成员调用，
> `Esc` 统一取消。

---

## 重点内容：你现在可以

- 让 Codex 成员持续使用同一条原生 thread：Asterline 会创建或恢复 thread ID，
  后续消息、模型选择、工具事件、思考摘要和需要用户决定的原生审批都进入这条
  thread。重启 Asterline 后仍会尝试恢复它；无法恢复时会明确提示，而不是悄悄伪造
  一段上下文。
- 打开 `/team` 就看到本机实际发现的模型与原生权限默认值。模型目录在本次运行中
  共享缓存；选中成员的 **model** 后按 `t` 才会重新取数，避免每次打开抽屉都反复
  启动 CLI。模型支持的 reasoning 也只在该模型实际声明时显示和传递。
- 用 `@成员 /attach` 或 `/attach 成员` 进入对应 CLI 的交互式终端。这里才是
  Codex、Claude、Grok、Agy 原生 `/model`、`/permissions`、`/compact` 等控制命令
  的真实运行位置；退出后 Asterline 会在可以安全识别会话时导入新消息。
- 直接用 `ast update` 更新受管理安装：Windows Setup 保持原有的校验更新流程；
  官方 Homebrew Formula 安装则执行受限的 `brew update` 与该 Formula 的升级。便携包、
  `.deb`/`.rpm`、DMG 与源码构建绝不会被猜测性覆盖。

---

## 概览

Asterline v0.2.8 是一次以会话连续性、真实后端能力和可预期交互为主的维护版本。
Codex 的默认运行方式升级为持久 App Server；Claude、Grok 和 Agy 继续保存各自原生
session/conversation ID。Team 编辑器的模型、权限、会话和成员显示均改为由真实 CLI
目录与已保存配置驱动，而不是按后端名硬编码一张通用表。

本版没有数据库 schema 迁移。现有 team 文件继续兼容；保存后只会写入你在 Team
编辑器明确选择的成员设置。

## 新功能

### Codex：持久 App Server 会话

Codex 成员现在通过 `codex app-server` 工作，而不是每条消息启动一次 `codex exec`。
Asterline 保存 App Server 返回的 thread ID，在下一轮和下次启动时恢复同一原生会话。
这使上下文、工具过程、模型目录和原生审批有了稳定的生命周期，也让 Asterline 不必
把交互式 TUI 命令伪装成普通 prompt。

原生审批请求会出现在 Asterline 的现有审批流中；`/approve` 和 `/reject` 只作用于
仍然存活的同一条 Codex thread。线程已结束时会明确报出无法送达，不会显示成已批准。

### Team：按真实能力显示模型、权限和会话

启动时会异步发现已安装后端与模型目录，结果在整个 Asterline 运行期间复用。Codex
从 App Server `model/list` 读取模型和每个模型自己的 reasoning 选项；Claude 从本地
配置读取可用模型与第三方网关别名；Grok 与 Agy 使用各自 CLI 的实际输出。选模型时，
左右键只在该模型声明的 effort 中移动，浏览不会篡改既有设置。

`permission mode` 同样按后端的本机语义显示和发送：Codex 映射为 App Server
`approvalPolicy`，Claude 使用其 CLI permission mode，Grok 使用 ACP/CLI 权限策略，
Agy 只显示和使用它实际支持的 execution mode。非 Codex 成员不再显示无意义的
`Codex transport` 字段。

### 技能和原生命令边界更清楚

`@成员 /` 只补全该成员真正可调用的技能与 `/attach`。Claude 已启用插件、命名空间
命令和本机/项目技能遵守实际范围；Agy 读取工作区、全局和 builtin skills 根。不会再把
另一位成员的技能混入当前成员，也不会扫描未启用插件的缓存目录。

原生 CLI 的交互式命令不再被声称为“透传”。Asterline 只将已发现的 prompt-invocable
skill 交给非交互 runner；其余控制请通过 `/attach` 进入原生终端。这一边界避免了
`/model` 被转换成错误 prompt 或看似成功但没有生效的权限操作。

## 交互调整

- `/exit` 立即退出 Asterline；活跃工作会走既有的收尾与取消路径。
- `/abort` 已移除：无 overlay 时按 `Esc` 取消活跃工作。Runs 抽屉中的活跃任务不会再
  把不存在的 `/abort` 填入编辑框。
- `/model`、`/effort` 和 `/skills` 不再是 Asterline 的全局命令。模型在 `/team` 中
  选择；技能用 `@成员 /技能`；原生模型/权限命令用 `/attach`。
- `/` 补全保持名称为白色、说明为浅灰色；选中项仅变为蓝色文字，不再整行铺蓝色背景。
  补全插入后保留一个空格，便于继续输入参数。
- 顶部成员列表使用紧凑的 `Builder · codex` 形式，保留成员名的后端色彩并将 backend
  设为浅灰色；会话策略会明确显示已绑定 session ID、`select a session` 或 fresh 状态。

## 会话与导入

Claude、Grok 与 Agy 的运行仍会保存其原生 session/conversation ID；Asterline 使用
该 ID 进行后续恢复。Asterline 可列出本地 Codex、Claude 和 Grok 历史；Agy 的本地
历史文件格式尚未作为 Asterline picker 的输入，仍可在 Team 中手动填写 conversation
ID。

原生 attach 返回时，导入遵循 fail-closed 原则：只有已绑定会话，或 Claude 可由谱系
唯一证明的 fork，才导入并认领消息。无法证明归属的 fresh 并发会话不会被“猜最近文件”
而串到错误成员。

## 升级提醒

### 旧的 Codex `exec` 不是默认运行路径

已保存的 Codex 成员会在下一次运行时使用 App Server。若原生 thread 无法恢复，
Asterline 会创建新 thread 并给出恢复提示；Asterline 自己持久化的聊天记录保持可见。

### 取消、模型与技能命令已收口

如果你有文档、脚本或肌肉记忆依赖 `/abort`、`/model`、`/effort` 或 `/skills`，请改用
`Esc`、`/team`、`@成员 /技能` 或 `/attach`。这不是删除功能：它把仅能在原生 TUI 中
完成的操作交还给对应 CLI，避免非交互模式静默失效。

### Agy 会话 ID 仍需手动选择

Agy 原生 CLI 支持用 conversation ID 恢复会话，但 Asterline 尚未把其未验证的本地
历史文件格式作为可扫描数据源。请在 `/team` 的 session id 字段手动填入，或进入原生
`agy` 使用其 `/resume` picker。
