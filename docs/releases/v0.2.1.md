# Asterline v0.2.1

Asterline v0.2.1 focuses on cross-platform operation, bounded resource use,
adapter protocol correctness, and durable conversation state. It adds a native
Windows release while hardening cancellation, approvals, persistence, imports,
and terminal rendering under failure and high-volume output.

## Highlights

- Added first-class Windows 10/11 x86-64 support. Executable discovery honors
  `PATHEXT`, verification uses `COMSPEC`, configuration resolves
  `USERPROFILE`/`CODEX_HOME`, SQLite is bundled for MSVC, and releases include
  native `.zip` archives.
- Added recursive process-tree cancellation on Windows with Job Objects and on
  Unix with process groups. Backend, verification, model-discovery, and PTY
  workers are tracked and reaped instead of leaving descendants behind.
- Bounded protocol lines, messages, tool details, PTY buffers, verification
  output, imports, runtime queues, and per-frame TUI work. Visible truncation
  markers distinguish shortened output from complete output, while a priority
  control channel keeps abort and shutdown responsive during stream floods.
- Hardened backend adapters. Codex and Claude prompts use stdin; successful
  completion now requires the backend's terminal result event. Grok ACP now
  negotiates advertised authentication, disables auto-update, sends graceful
  cancellation, observes terminal stop reasons, and no longer treats `auto`
  permission mode as permission to approve dangerous requests.
- Strengthened run and approval isolation. Explicit run IDs are scoped to the
  active conversation, sibling mode approvals resolve together, removed
  members cannot retain actionable approvals, and invalid checklist owners or
  unknown dispatch targets fail clearly instead of leaving a run stuck.
- Made critical persistence paths fail closed and grouped compound SQLite
  writes into transactions. Store errors no longer allow verification, repair,
  completion, or runtime reconfiguration to continue with memory and disk in
  conflicting states; short lock contention is handled with a busy timeout.
- Improved TUI correctness. User messages and control commands wait for
  runtime acknowledgement, runtime disconnects are visible, no-argument
  commands reject accidental text, fenced Markdown examples cannot execute
  teammate envelopes, and grapheme-aware editing preserves combining marks and
  emoji.
- Hardened team and mode configuration. Member handles reject reserved,
  whitespace, and control values; `all` remains reserved for broadcast; and
  brainstorm requires at least two unique participants.
- Pinned GitHub Actions to immutable commit SHAs, added Dependabot tracking for
  action updates, and added real Windows link-and-execute coverage to CI.

## Compatibility notes

- Custom `MemberRunner` implementations must accept
  `SyncSender<AgentEvent>` instead of `Sender<AgentEvent>`. This intentionally
  propagates runtime backpressure to protocol producers.
- Team files with invalid or reserved member handles are now rejected. Rename
  handles such as `all`, trim surrounding whitespace, and remove control
  characters before loading them.
- Brainstorm participant lists must contain at least two distinct members;
  repeated entries no longer count as separate participants.
- Grok `auto` permission mode follows ACP safety semantics: requests that still
  require approval are surfaced to Asterline instead of being automatically
  allowed. `bypassPermissions` remains the explicit bypass setting.

## 中文摘要

- 新增 Windows 10/11 x86-64 原生支持：按 `PATHEXT` 查找命令、通过
  `COMSPEC` 执行验证、识别 `USERPROFILE`/`CODEX_HOME`、为 MSVC 内置
  SQLite，并发布原生 `.zip` 包。
- Windows 使用 Job Object、Unix 使用进程组递归取消进程树；后端、验证、模型
  发现和 PTY worker 都会被跟踪与回收。
- 为协议行、消息、工具详情、PTY、验证输出、导入、运行时队列和每帧 TUI 工作量
  增加明确上限；截断会显示标记，`/abort` 和退出控制不再被大量流事件堵住。
- 完善 Codex、Claude、Grok 和 Agy 的结束事件、stdin、ACP 鉴权、取消与权限语义，
  避免进程以 0 退出但协议结果不完整时被误报成功。
- Run ID、审批和恢复数据现在严格限制在当前对话；同一 Mode Run 的审批会联动
  处理，非法 owner、未知成员及移除成员不再造成永久卡住的工作流。
- SQLite 复合写入采用事务，关键状态持久化失败时停止后续调度，避免内存状态与
  磁盘状态分裂。
- TUI 现在等待 runtime 确认消息和控制命令，明确显示 runtime 断开；Markdown
  代码块中的协议示例不会被执行，组合字符和 ZWJ emoji 可按完整字素编辑。
- GitHub Actions 已锁定到不可变 commit SHA，并新增 Windows 真实编译执行门禁和
  action 依赖更新配置。

## Validation

The release gate covers formatting, warning-free Clippy, all Rust targets and
documentation tests, Windows MSVC builds, and Windows link-and-execute tests.
Real paid or authenticated backend smokes remain opt-in and are disabled unless
their `ASTERLINE_SMOKE_*` variables are set.
