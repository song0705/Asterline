# Asterline v0.2.8

[简体中文](v0.2.8.md)

> This release makes team conversations genuinely native-CLI sessions. Codex
> members no longer treat every turn as an isolated `exec`: they keep a
> resumable App Server thread, including model, approval, and tool events.
> The Team editor reads local CLI capabilities instead of guessing static
> settings. Interactive native commands open the native session; skills are
> routed only through the matching member; `Esc` is the common cancellation
> control.

---

## Highlights

- Keep a Codex member on one native thread. Asterline creates or resumes its
  thread ID; later prompts, model changes, tool events, reasoning summaries,
  and native approvals stay on it. After an Asterline restart it attempts to
  resume the thread and reports a recovery failure rather than inventing prior
  context.
- Opening `/team` shows locally discovered models and native permission
  defaults. Catalogs are shared for the lifetime of this Asterline process;
  select a member's **model** field and press `t` only to retry a failed lookup.
  Reasoning appears and is passed through only where that model actually
  declares it.
- Use `@member /attach` or `/attach member` for an interactive native terminal.
  This is where Codex, Claude, Grok, and Agy controls such as `/model`,
  `/permissions`, and `/compact` genuinely run. On return, Asterline imports
  new messages only when it can safely identify the session.
- Use `ast update` for managed installs. Windows Setup retains its verified
  updater; an official Homebrew install runs restricted `brew update` and a
  Formula-specific upgrade. Portable archives, `.deb` / `.rpm`, DMGs, and
  source builds are never guessed and overwritten.

---

## Overview

v0.2.8 is a maintenance release centered on session continuity, real backend
capabilities, and predictable interaction. Codex now defaults to a persistent
App Server; Claude, Grok, and Agy continue to retain their native
session/conversation IDs. The Team editor's model, permission, session, and
member displays come from actual CLI catalogs and saved configuration instead
of a backend-name-based generic table.

There is no database schema migration. Existing team files remain compatible;
saving writes only member settings explicitly selected in the Team editor.

## New capabilities

### Codex persistent App Server sessions

Codex members now use `codex app-server`, rather than launching `codex exec`
for every prompt. Asterline persists the App Server thread ID and resumes the
same native conversation for later turns and later launches. This gives context,
tool flow, model catalogs, and native approvals a stable lifecycle without
pretending that interactive TUI controls are ordinary prompts.

Native approval requests enter Asterline's existing approval flow. `/approve`
and `/reject` affect only the still-live Codex thread; a terminated thread is
reported as unreachable rather than shown as approved.

### Team shows real models, permissions, and sessions

Configured backends and model catalogs load asynchronously at startup and are
reused for the current Asterline process. Codex uses App Server `model/list`;
Claude reads local configuration and third-party gateway aliases; Grok and Agy
use their own CLI output. Left and right arrows change only the effort values
declared by the highlighted model, and browsing never changes a saved setting.

`permission mode` is also displayed and sent using each backend's own meaning:
Codex maps it to App Server `approvalPolicy`, Claude uses its CLI permission
mode, Grok uses ACP/CLI permission policy, and Agy exposes only execution modes
it supports. Non-Codex members no longer display the meaningless Codex
transport field.

### Clear skill and native-command boundary

`@member /` completes only callable skills for that member and `/attach`.
Enabled Claude plugins, namespaced commands, and local/project skills follow
their real scope; Agy reads workspace, global, and builtin skill roots. Skills
from another member are not mixed in, and disabled-plugin caches are not read.

Interactive native commands are no longer advertised as prompt pass-through.
Asterline sends only discovered prompt-invocable skills to non-interactive
runners; other controls go through `/attach`. This avoids turning `/model` into
an incorrect prompt or making a permission setting appear to have worked.

## Interaction changes

- `/exit` exits Asterline immediately; active work follows the existing cleanup
  and cancellation path.
- `/abort` is removed. With no overlay, press `Esc` to cancel active work.
- `/model`, `/effort`, and `/skills` are no longer global Asterline commands.
  Choose models in `/team`, invoke skills with `@member /skill`, and use
  `/attach` for native model and permission controls.
- `/` completion keeps names white and descriptions muted; selection changes
  text to blue without a full-width blue background. Accepted completion leaves
  a trailing space for arguments.
- The member header uses compact `Builder · codex` labels with a colored member
  name and muted backend. Session policy shows a bound ID, `select a session`,
  or fresh state explicitly.

## Sessions and import

Claude, Grok, and Agy runs retain their native session/conversation IDs for
later recovery. Asterline can list local Codex, Claude, and Grok history; Agy's
unverified local history format is not a picker input yet, so its conversation
ID can still be entered manually in Team.

Import after native attach is fail-closed: messages are imported and claimed
only for an already-bound session, or for a Claude fork uniquely proven by its
lineage. Ambiguous concurrent fresh sessions are not guessed from the newest
file and attached to the wrong member.

## Upgrade notes

### Legacy Codex `exec` is not the default path

Saved Codex members use App Server on their next run. If its native thread
cannot be resumed, Asterline starts a new thread with a recovery notice; its
own persisted chat history remains visible.

### Cancellation, models, and skills are intentionally scoped

If documentation, scripts, or muscle memory used `/abort`, `/model`, `/effort`,
or `/skills`, use `Esc`, `/team`, `@member /skill`, or `/attach` instead. This
does not remove the native capability: it returns controls that only work in a
native TUI to that CLI instead of silently failing in non-interactive mode.

### Agy session ID is still manual

Agy's native CLI can resume with a conversation ID, but Asterline does not yet
scan its unverified local history format. Enter the ID in `/team`, or open native
`agy` and use its `/resume` picker.
