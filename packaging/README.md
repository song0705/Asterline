# Third-party package definitions

This directory keeps version-pinned definitions for package-manager maintainers.
They install both `asterline` and its short `ast` alias. The Homebrew Formula
mirrors the published Homebrew tap; the AUR definition remains ready to submit
when that external service is available.

Advance an external package only after its Release's versioned asset, checksum,
and provenance are available. The package managers can intentionally be on
different versions.

## Homebrew (macOS)

`homebrew/Formula/asterline.rb` mirrors the published v0.2.5 macOS-only
Formula in the public `song0705/homebrew-asterline` tap. It pins the Apple
silicon and Intel portable archives by SHA-256. It deliberately does not support
Linuxbrew until the Linux release ABI is independently verified.

Users can install it with:

```bash
brew install song0705/asterline/asterline
```

Validate the published Formula with:

```bash
brew tap song0705/asterline
brew audit --strict --online --formula song0705/asterline/asterline
brew install --formula song0705/asterline/asterline
brew test song0705/asterline/asterline
```

## Arch User Repository

`aur/asterline` is a ready-to-submit stable source package for `x86_64` and
`aarch64`. It intentionally remains pinned to v0.2.3 rather than advancing
with Homebrew automatically. It pins the exact source commit and SHA-256, then
asserts that the source manifest reports the expected package version before
building. The v0.2.3 tag is annotated but not GPG-signed, so the package
intentionally pins its resolved release commit rather than trusting a mutable
tag reference.

The source package is preferred over v0.2.3's Linux binary archives: those
historical archives require `GLIBC_2.39` and dynamically link `libsqlite3`.
The AUR definition compiles against the target Arch system and declares its
runtime SQLite dependency explicitly.

Copy this directory into the `asterline` AUR Git repository, then validate and
regenerate metadata on Arch before pushing it:

```bash
cd asterline
makepkg --verifysource
makepkg --syncdeps --cleanbuild
makepkg --printsrcinfo > .SRCINFO
git diff --exit-code -- .SRCINFO
```

After publication, users can install it with `yay -S asterline` (or another
AUR helper).

`makepkg --verifysource` can repeat the downloaded source-archive checksum
offline. A clean-chroot Cargo build still needs registry access because the
upstream release does not yet publish a vendored dependency archive.

## Linux Release packages

Starting with v0.2.6, each Linux architecture uses the same visible asset
prefix, modeled after the established `Linux-arm64` / `Linux-x86_64` layout:

| CPU architecture | Portable archive | Debian / Ubuntu | RPM Linux |
| --- | --- | --- | --- |
| ARM64 | `asterline-v<version>-Linux-arm64.tar.gz` | `asterline-v<version>-Linux-arm64.deb` | `asterline-v<version>-Linux-arm64.rpm` |
| Intel / AMD 64-bit (`x86_64`) | `asterline-v<version>-Linux-x86_64.tar.gz` | `asterline-v<version>-Linux-x86_64.deb` | `asterline-v<version>-Linux-x86_64.rpm` |

The workflow builds Debian packages from the already verified GNU/Linux
archives, derives runtime dependencies with `dpkg-shlibdeps`, then installs,
runs, and removes each one on Debian 12 and Ubuntu 24.04. It builds RPM packages
from the same verified archives in Rocky Linux 8, retains automatic RPM shared
library dependencies, then repeats installation, execution, and removal on
Fedora 44. These are GitHub Release assets, not APT or DNF repositories: a
future repository would need its own signing key and hosting.

After downloading the matching asset from a Release that contains it, install
it with one of these commands:

```bash
sudo apt install ./asterline-v<version>-Linux-x86_64.deb
sudo dnf install ./asterline-v<version>-Linux-x86_64.rpm
ast --help
```

The existing v0.2.3 Release predates all Linux package assets. v0.2.5 contains
the earlier Debian-only pair; v0.2.6 is the first Release with the visible
architecture naming and matching RPM packages.

## Release update checklist

After every published Asterline Release, update the Formula version, archive
URLs, and SHA-256 values. For the AUR package, resolve the annotated tag to its
commit, pin that commit and its archive SHA-256, update `pkgver`/`pkgrel`, then
regenerate `.SRCINFO` with `makepkg`. The Debian and RPM package names and
checksums are generated by the release workflow. Run the validation procedures
above before pushing any external package repository. Do not use `releases/latest`
or `SKIP` for a versioned release archive.
